# WordDrill — 极简英语学习闪卡 App

## Problem Statement

英语学习者需要一种低压力的方式来被动加深对单词的记忆。市面上的闪卡 App 普遍引入了考试、评分、记忆曲线算法、每日打卡、提醒通知等机制，给用户带来心理负担。用户想要的是一个纯粹"刷卡片"的工具——不断滑动浏览中英文对照的卡片，靠被动重复来加深记忆，仅此而已。此外还需要简单的数据统计来感知自己的进度，以及词库管理能力来定制学习范围。

## Solution

WordDrill 是一个 Android 原生 App，提供极简的闪卡浏览体验。每张卡片同屏显示英文单词（含词性）和中文释义，用户左右滑动切换。不评分、不判对错、无记忆算法、无打卡提醒。App 预置 CET-4、CET-6、考研英语三个词书，用户可新建和管理自定义词书。所有数据本地存储，完全离线，无后端无账号。提供简单的刷卡统计和当前词书进度，支持整库导出/导入文件以迁移数据。

## User Stories

### 刷卡（主功能）
1. 作为学习者，我想打开 App 就直接进入刷卡界面，这样我能立刻开始复习，不需要多余的启动步骤。
2. 作为学习者，我想每张卡片同屏显示英文单词和中文释义，这样我不需要翻面就能同时看到两种语言。
3. 作为学习者，我想看到单词的词性（名词/动词等），这样我能理解单词的用法。
4. 作为学习者，我想一个单词的所有词性和释义合并在一张卡片上，这样同一个单词不会被拆成多张碎片化的卡。
5. 作为学习者，我想向右滑动切换到下一张卡片，这样我能按顺序推进学习。
6. 作为学习者，我想向左滑动切回上一张卡片，这样我能回看刚刷过的内容。
7. 作为学习者，我想在卡片顶部看到当前词书的名字，这样我知道自己正在刷哪个词库。
8. 作为学习者，当我滑到最后一张卡片还想继续时，我想看到一个"已是最后一张"的提示，这样我知道已经刷完了一遍。
9. 作为学习者，当我滑到第一张卡片还往前滑时，我想看到一个"已是第一张"的提示，这样我知道到了起点。
10. 作为学习者，我不想看到任何"记得/不记得"按钮或评分机制，这样刷卡时没有心理压力。

### 词库与词书管理
11. 作为学习者，我想在「库」Tab 看到所有词书的列表，这样我能了解有哪些词库可用。
12. 作为学习者，我想在词书列表中选择一个词书作为当前词书，这样主界面刷卡时就刷这个词书。
13. 作为学习者，我想新建自定义词书，这样我能按自己的需求组织单词。
14. 作为学习者，我想删除词书（预置词书除外），这样我能清理不再需要的自定义词书。
15. 作为学习者，我想重命名词书，这样我能给自定义词书起更有意义的名字。
16. 作为学习者，我想点进某个词书看到它的词条列表，这样我能查看该词书包含哪些单词。
17. 作为学习者，我想在词条列表里新增词条（单词、词性、释义），这样我能往词书里补充内容。
18. 作为学习者，我想编辑已有词条的内容，这样我能修正错误的释义或补充信息。
19. 作为学习者，我想删除词条，这样我能从词书里移除不需要的单词。

### 统计
20. 作为学习者，我想看到今天刷了多少张卡片，这样我能感知今天的学习节奏。
21. 作为学习者，我想看到累计刷了多少张卡片，这样我能感知总体的学习量。
22. 作为学习者，我想看到当前词书的进度（已刷 X / 总 Y，百分比），这样我能知道自己在这个词书上推进了多少。

### 数据与设置
23. 作为学习者，我想导出我的全部数据为一个文件，这样我能在换手机时迁移数据。
24. 作为学习者，我想把导出的数据文件导入到新设备，这样我能在新手机上恢复学习进度。
25. 作为学习者，我可以在导出时填写一个昵称，这样导入时能识别这是谁的数据。
26. 作为学习者，我想在「我的」Tab 切换深色/浅色/跟随系统主题，这样我能在不同光线环境下舒适使用，也能让 App 自动适配系统设置。
27. 作为学习者，我想在「我的」Tab 查看关于页面，这样我能了解 App 版本等信息。
28. 作为学习者，我想在设置里隐藏音标，这样刷卡时只看单词和释义，更简洁。
29. 作为学习者，我想开启极简模式，这样刷卡时隐藏导航栏，全屏沉浸不被打扰。
30. 作为学习者，我想切换导航栏风格（浮动胶囊/底部栏），这样我能选择自己喜欢的导航样式。
31. 作为学习者，我想在刷卡页点锁定按钮隐藏导航栏，这样我能沉浸式刷词不被打扰，需要切换时再点解锁。

## Implementation Decisions

### 整体架构
- **语言**：Kotlin 2.4.x。
- **UI 框架**：Jetpack Compose，使用 Compose BOM 管理版本。
- **最低 SDK**：API 26（Android 8.0）。compileSdk / targetSdk = 36。
- **架构模式**：单 Activity + MVVM。使用 ViewModel + StateFlow 驱动 Compose UI。Compose Navigation 管理 Tab 间导航。
- **构建**：Gradle Kotlin DSL（build.gradle.kts），AGP 8.13.x，JDK 17。

### 依赖注入
- **引入 Hilt**。押注 App 未来会生长到中型规模。使用 `@HiltAndroidApp`、`@Inject`、`@HiltViewModel`。所有 ViewModel 通过 Hilt 注入 Repository。

### 数据库（Room 2.8.x）
- **全局词条池模型**。一个单词在词池中只存一份，多个词书通过引用共享。
- 按"拼写 + 词性"去重。同一拼写不同词性是不同记录。
- 一个单词一条记录，该单词的所有词性/释义作为义项列表存在一起（一张卡 = 一个单词）。
- **表结构**（关系示意，非精确 DDL）：
  - `word` 表：`word_id`（自增主键）、`text`（单词文本）、`phonetic`（音标，如 /əˈbændən/，可为空）
  - `sense` 表：`sense_id`（主键）、`word_id`（外键）、`pos`（词性）、`meaning`（中文释义）
  - `book` 表：`book_id`（主键）、`name`（词书名）、`is_preset`（是否预置词书，预置不可删）
  - `book_word` 关联表：`book_id`（外键）、`word_id`（外键），表示某词书包含某词条
  - `swipe_log` 表：`log_id`（主键）、`book_id`、`word_id`、`timestamp`，记录每次向右滑（前进）事件
- 统计数据全部从 `swipe_log` 聚合计算，不单独存储进度。

### 预置词库
- 三个预置词书：CET-4、CET-6、考研英语。
- 词库数据以 `assets/words.json` 打包进 App。
- 首次启动检测是否已导入（用 DataStore 存标记），未导入则在后台线程解析 JSON 并写入 Room。
- 之后所有查询走 Room。
- 用户后续可指定词库范围，通过替换/扩展 JSON 资源实现。

### 卡片浏览交互
- 主界面使用 Compose `HorizontalPager` 实现左右滑动。卡片展示顺序：单词 → 音标（若有）→ 分割线 → 义项列表（词性+释义同行，一行一义项）。
- 向右滑（前进到下一张）触发统计 +1，写入 `swipe_log`。
- 向左滑（回看上一张）不计数。
- 线性推进，不循环。到头时显示提示（"已是第一张/最后一张"），提示不计数。
- 顶部纯文字展示当前词书名，不可点击，不可交互。

### 当前词书状态
- App 用 DataStore 记住"当前选中的 book_id"，下次打开直接继续刷该词书。
- 切换词书的唯一入口在「库」Tab。

### 页面结构（三 Tab）
- 底部导航三个 Tab：「刷」「库」「我的」。
- **「刷」Tab**：全屏单卡片。顶部词书名（纯展示）+ 中间英文（含词性）与中文释义对照 + 左右滑切换。
- **「库」Tab**：词书列表。支持选择当前词书、新建词书、删除（仅自定义）、重命名。点进某词书进入该词书的词条列表，支持词条增删改。
- **「我的」Tab**：统计数据（今日刷卡数、累计刷卡数、当前词书进度）+ 软件设置（主题切换深色/浅色/跟随系统、关于页）+ 数据导出/导入。

### 数据导出/导入
- 整库导出为一个文件（JSON 或 SQLite .db）。
- 使用 Android SAF（Storage Access Framework）让用户选择保存/读取位置。
- "帐号"退化为导出文件里一个可选的昵称标签，不涉及登录或多档案。
- 导入时覆盖或合并本地数据（导入策略需进一步明确）。
- 设备内无多用户/多档案概念，所有数据为设备级单用户。

### 主题
- 支持深色/浅色/跟随系统三种主题模式，设置项在「我的」Tab。跟随系统模式使用 Android 系统的深浅色配置，自动适配。
- 隐藏音标：设置开关，开启后刷卡页不显示音标。
- 极简模式：设置开关，开启后刷卡页隐藏导航栏，纯全屏沉浸。
- 导航栏风格：可选浮动胶囊（iOS 18+ 风格，默认）或底部栏。
- 锁定模式：刷卡页顶部锁形图标，点击锁定后导航栏 spring 动画滑出消失，再点击（图标变解锁态）恢复。锁定时跳过按钮也隐藏，纯沉浸。切 Tab 自动解锁。

## Testing Decisions

### 测试哲学
- 只测外部行为，不测实现细节。测试应能在不改动的情况下通过重构。
- 接缝越少越好。理想是单一接缝覆盖全部行为。

### 主接缝：Compose UI 集成测试
- 使用 `composeTestRule` 配合内存版 Room 数据库（in-memory Room）。
- 通过 UI 驱动整个 App 的用户可见行为：刷卡、切 Tab、看统计、进词库增删改词条、切词书。
- 覆盖范围：刷卡计数逻辑、统计聚合（今日/累计/进度）、词书选择、词条 CRUD、词书进度、到头提示。
- 这一个接缝覆盖绝大多数行为。

### 副接缝：导出/导入序列化单测
- 仅针对数据导出/导入的 JSON 序列化与反序列化做纯逻辑单测。
- 原因：这一块触碰 Android 文件系统（SAF），通过 UI 测试驱动不划算且脆弱。
- 验证导出文件格式的正确性和导入的完整性。
- 这是唯一被迫单独开的窄口。

### Prior Art
- 仓库为 greenfield，无既有测试可参照。

## Out of Scope

- **记忆曲线算法**（SRS/间隔重复）：不做。纯被动浏览。
- **评分/对错判断**（"记得"/"不记得"按钮）：不做。
- **每日打卡、连续天数、提醒通知**：不做。
- **后端服务、云同步、账号登录**：不做。完全离线。
- **多用户/多档案**：不做。设备级单用户。
- **音频发音**：不做（本次范围）。
- **图片、例句**：不做（本次范围）。
- **复习模式/测试模式**：不做。只有线性浏览。
- **Web 版/iOS 版**：不做。仅 Android。

## Further Notes

- **预置词库数据获取**：CET-4/CET-6/考研的词表需从公开考纲来源获取，含词性、中文释义与音标（IPA）。数据准备是独立的子任务，需确保版权合规。
- **导入策略待定**：导入数据时是"覆盖本地"还是"合并去重"需要在实现阶段进一步明确，作为 ticket 级决策。
- **Hilt 的选择**是押注未来扩展。如果 App 长期保持极简，手动构造本是更轻的选择；但如果未来扩展到十几个 ViewModel，Hilt 的早期投入会回本。
- 技术版本号（Kotlin/AGP/Compose BOM 等）为 2026 年 7 月核实值，实现时以当时最新稳定版为准。
